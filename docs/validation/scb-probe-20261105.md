| 场景 | 进程返回码 | UVM W/E/F | 原环境读回 | 诊断结果 |
|---|---:|---:|---|---|
| raw Completion golden | 0 | 0/0/0 | 不适用 | 两种 DWORD 顺序 × Tag 高两位四种组合，共 8 例通过 |
| SCB 关闭 | 0 | 0/0/0 | PASS | request `scb_present=0`；3 个 Completion 均 `driver_matches=1, scb_pending=0` |
| SCB 开启 | 0 | 3/1/0 | PASS | `matched=1 unexpected=3 mismatched=0 pending=0 trackers=0` |
| SCB 开启并临时登记 | 0 | 0/0/0 | PASS | `matched=2 unexpected=0 mismatched=0 pending=0 trackers=0` |

三组 env 对照使用相同请求 `tag=000, req_id=4cac`，并收到相同的三个 Completion，
其 `byte_count` 依次为 137、74、10；driver 在三组中都能匹配。SCB 开启但未登记时，
发送前 `registered_before_send=0`，三个 Completion 到达时 `scb_pending=0`，因此产生三个
Unexpected Completion。只在 `on_tag_assigned` 调用现有 `register_pending` 后，三个 Completion
到达时 `scb_pending=1`，SCB 完整匹配并清空 pending/tracker，且业务读回结果不变。

结论：本次证据支持 bind/bridge 路径缺少 SCB pending request 登记；不支持 Completion Tag
解析错误。raw golden 同时验证了 Tag[9:8] 的四种组合和两种 Header DWORD 顺序。

注意：未登记的 SCB-on 场景虽然 `simv` 返回 0，但 report_phase 明确产生 1 个 UVM_ERROR，
因此该场景按 UVM 结果判定为预期复现，而不是通过。
